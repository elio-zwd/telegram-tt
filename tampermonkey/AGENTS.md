# Tampermonkey 插件开发规则

本文件适用于 `tampermonkey/**`。同时遵守仓库根目录 `AGENTS.md`；当根规则主要面向 Telegram TT 桌面源码、与油猴脚本的技术形态不一致时，以本文件的目录级规则为准。

## 1. 技术范围

- 油猴脚本使用原生 JavaScript、浏览器 DOM API 和 Shadow DOM。
- 不把 Teact、SCSS Modules、GramJS、Global State 或桌面应用本地化规范强行套用于油猴脚本。
- 不新增第三方运行时依赖；优先复用现有函数、状态结构和页面公开 DOM。
- 只修改当前需求必需的文件，不顺带重构、格式化或迁移无关代码。
- Web A 与 Web K 是独立适配目标。修改一个平台时，不得顺带修改另一个平台，除非任务明确要求。

## 2. 平台与架构边界

- Web A 脚本：`telegram-media-continuity.user.js`。
- Web K 脚本：`telegram-media-continuity-web-k.user.js`。
- 平台差异应封装在各自适配逻辑内，不得用未经验证的选择器跨平台复用。
- 共用能力需要先形成明确的共享核心方案，再在独立架构任务中迁移；不得在功能 PR 中临时进行大规模统一。
- 一个功能 PR 应聚焦一个平台或一个明确的共享层，不同时承担平台迁移和产品功能扩展。

## 3. Telegram 接入安全边界

- 不调用 Telegram API、Bot API 或 MTProto。
- 不要求用户提供 API ID、API Hash、Bot Token 或账号凭据。
- 不读取、枚举或调用 Telegram 的 webpack 私有模块、内部运行时对象或未公开函数。
- 不读取 Telegram IndexedDB、缓存数据库或本地认证数据。
- 不绕过受保护内容、付费媒体、频道权限、下载限制或 Telegram 安全控制。
- 页面结构不匹配时必须安全失效，不得导致白屏、阻断点击、持续滚动或破坏 Telegram 原功能。

## 4. 隐私与本地数据

- 不上传、收集或发送聊天内容、账号数据、频道信息或媒体地址。
- 调试日志不得输出聊天正文、频道名称、用户名、账号标识或完整媒体 URL。
- DOM 探测结果必须脱敏，只保留选择器命中、布尔状态、元素类型和必要的非内容标识。
- 本地持久化仅保存完成功能所需的最小数据，并设置版本、数量上限、损坏数据清理和淘汰策略。
- 不持久化可直接还原媒体内容的 URL、Blob 地址或聊天正文。

## 5. DOM 选择器与真实页面验证

- 上游 Telegram Web 源码只能作为设计线索，不能代替线上真实页面确认。
- 新增或修改选择器前，必须确认目标平台、页面状态和元素生命周期。
- 优先使用稳定的公开属性、语义结构和多证据匹配，避免依赖随机类名、文本内容或媒体 URL。
- 选择器证据冲突时停止对应自动行为，不得猜测目标元素。
- 必须考虑 Telegram 消息列表的虚拟化：目标不在 DOM 不等于目标不存在。
- 禁止通过无界滚动、无限 MutationObserver 重试或反复点击来寻找目标。
- 需要调用 Telegram 官方 DOM 行为时，必须先在真实页面验证该行为及事件时序，并限制为有限次数。

## 6. 自动操作与生命周期

- 所有自动点击、滚动、重试和等待必须有明确触发条件、次数上限和超时。
- 用户手动操作优先于插件自动操作；插件不得与用户持续争夺焦点、播放状态或滚动位置。
- MutationObserver、事件监听器、计时器、动画和媒体回调必须在查看器关闭、页面切换或会话销毁时清理。
- 异步回调必须校验当前会话、当前查看器和序列 ID，避免旧任务作用于新页面。
- 媒体尚未成功加载时，不得把它记录为“最后成功显示媒体”。
- 自动行为失败时应恢复为 Telegram 原始行为，而不是阻止关闭或导航。

## 7. 代码风格

- 沿用现有 userscript 的函数命名、常量、状态类和日志风格。
- 优先使用早返回，避免深层嵌套。
- 固定超时、重试次数和阈值使用模块顶部常量，不在函数内散落魔法数字。
- 函数保持单一职责；DOM 探测、目标确认、关闭快照、定位和高亮分别处理。
- 仅为复杂时序、隐私边界和降级逻辑添加中文注释，不保留临时调试代码。
- 不保留未使用、推测性或“以后可能用到”的通用工具函数。
- 不使用 `eval`、动态脚本注入或页面私有模块劫持。

## 8. Shadow DOM 与样式

- 插件控制界面优先放入独立 Shadow DOM，避免污染 Telegram 页面样式。
- 样式必须限定在插件宿主或 Shadow Root 内，不添加会影响 Telegram 全局元素的宽泛规则。
- 对 Telegram 消息的临时高亮应可自动清理，不永久修改 class、style 或页面结构。
- 新增界面不得遮挡 Telegram 官方关闭、导航、播放、输入和滚动控件。

## 9. 版本与文档

- 修改 userscript 行为时更新头部 `@version`。
- 同步更新 `tampermonkey/README.md` 中的平台、功能、限制和验收状态。
- 重要 DOM 兼容修复应更新对应 Plan、Task 或交接文档。
- 文档必须区分：设计推断、静态检查结果、GitHub CI 结果和真实浏览器验收结果。
- 不得把未执行的命令、未观察的 DOM 或未完成的浏览器场景写成“已通过”。

## 10. 验证要求

修改 JavaScript 后至少执行并记录真实输出：

```powershell
node --check tampermonkey/<目标脚本>.user.js
git diff --check <base>...HEAD
git diff --name-status <base>...HEAD
git status --short
git rev-parse HEAD
```

- 根目录规则要求不新增测试文件，本目录继续遵守。
- 静态检查不能替代真实 Telegram Web A/Web K 浏览器验收。
- 无本地终端时只做静态阅读和 GitHub 差异核对，并明确标记命令尚未执行。
- 无真实浏览器控制能力时，不得声称 DOM 选择器、媒体时序或关闭定位已经通过。
- 浏览器验收必须记录操作系统、浏览器、Tampermonkey 版本、页面平台、复现步骤和结果。

## 11. 多 AI 对话与 GitHub 协作

- 一个对话只负责一个任务、一个独立分支和一个 PR。
- 同一 userscript 同一时间只能由一个对话写入；其他对话不得在不同分支同时修改相同脚本。
- 开始修改前检查开放 PR 和近期提交，发现同文件或同逻辑冲突时先报告。
- 每次写入前重新读取目标分支上的最新文件，避免覆盖其他提交。
- 对话之间通过分支、Commit、PR 描述、评论和 `docs/` 交接，不依赖聊天记忆。
- 不强推、不删除他人分支、不关闭或合并他人 PR。
- 未经用户明确授权不得合并 PR。

## 12. Commit 与 PR

- Commit 标题使用“英文类型: 中文描述”，保持原子性。
- PR 描述至少包含背景与目标、实现方式、修改文件、验证情况、未验证项、风险、回滚和本地验收步骤。
- 功能尚未完成或真实浏览器尚未验收时保持 Draft。
- 完成前重新审查差异，确认没有修改 Web A/Web K 之外的平台或桌面源码。
