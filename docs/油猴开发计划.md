| 功能 | 油猴可行性 | 第一版建议 |
|---|---:|---|
| 检测媒体查看器打开、关闭 | 高 | 实现 |
| 图片加载完成后等待 5 秒 | 高 | 实现 |
| 视频播放结束后进入下一项 | 高 | 实现 |
| 点击 Telegram 官方下一项按钮 | 高 | 实现 |
| 鼠标悬停暂停图片倒计时 | 高 | 实现 |
| 标签页后台、窗口失焦时暂停 | 高 | 实现 |
| 用户手动暂停后不自动跳转 | 中高 | 实现，但需要区分脚本暂停和用户暂停 |
| 到末尾停止、不循环 | 高 | 实现 |
| Shadow DOM 隔离控制条 | 高 | 实现 |
| 设置保存在浏览器本地 | 高 | 实现 |
| 最多保留 100 条续播记录 | 高 | 实现 |
| 按频道隔离浏览位置 | 中高 | DOM 探测确认后实现 |
| 按话题隔离浏览位置 | 中 | 找不到稳定话题标识时降级 |
| 精确记录消息 ID | 中 | 必须从消息链接、URL 或稳定 DOM 属性获取 |

| 自动加载频道后续历史媒体 | 低至中 | 不纳入第一版承诺 |
| 精确判断频道、群组、私聊 | 中 | 找不到可靠证据时安全失效 |

| 主动预加载下一张原图 | 低 | 不做，依赖 Telegram 自身预加载 |
| 自动保存、去重、文件大小检测 | 低至中 | 油猴第一版不要做 |

# 二、推荐第一版范围

建议把油猴第一版定义成：

> **控制 Telegram 官方媒体查看器自动执行“下一项”，并在能够可靠识别媒体位置时提供续播入口。**

## 第一版正式纳入

1. 只运行于：

```text
https://web.telegram.org/a/*
```

2. 识别官方媒体查看器。

3. 在查看器中注入独立控制条：

- 连续浏览开关；
- 暂停／继续；
- 图片停留时间，第一版固定或默认 5 秒；
- 状态提示；
- 关闭控制条。

4. 图片行为：

- 当前活动图片加载完成后开始计时；
- 鼠标悬停时暂停；
- 鼠标移开后从完整 5 秒重新计时；
- 浏览器标签页隐藏时暂停；
- 窗口失焦时暂停；
- 图片被缩放或拖动时，能够识别则暂停；
- 到时点击官方“下一项”。

5. 视频行为：

- 监听当前活动 `<video>` 的 `ended`；
- 连续模式开启且未暂停时点击官方“下一项”；
- 用户手动暂停时停留；
- 自动播放失败时显示“点击视频继续”，不直接跳过。

6. 队列末尾：

- 下一项按钮不存在、禁用，或者点击后媒体未变化；
- 停止连续浏览；
- 不循环；
- 显示“已到当前媒体末尾”。

7. 本地状态：

- 连续浏览开关；
- 图片时间；
- UI 是否折叠；
- 最近媒体位置；
- 数据版本；
- 最多 100 条；
- 损坏自动清理。

8. 续播位置：

- 仅保存能够确认的频道、话题、消息和相册序号；
- 只有确认目标仍可打开时才显示“继续上次位置”。

## 第一版明确暂缓

- 主动请求更多历史媒体；
- 自动保存媒体；
- 文件大小限制；
- 下载去重；
- 完整媒体总数；
- 只图片／只视频筛选；
- 反向连续浏览；
- 等待频道发布新媒体；
- 跨频道播放列表；
- 从消息 ID 强制调用 Telegram 内部状态或函数。

这些功能并非完全做不到，而是油猴脚本实现后会大量依赖 Telegram 私有内部对象，页面升级后容易整体失效。

# 三、DOM 探测方案

这里不应提前写死任何类名。Telegram Web 的构建类名、组件结构和无障碍文本都可能变化。

建议先增加一个只用于开发的 **DOM 探测模式**。

## 1. 媒体查看器识别

通过 `MutationObserver` 观察页面顶层节点变化。

发现新浮层时，不直接依赖类名，而是按照特征确认：

- 节点当前可见；
- 位于页面主要内容之上；
- 包含可见的 `<img>` 或 `<video>`；
- 包含关闭控件；
- 可能包含上一项和下一项操作；
- 媒体尺寸达到合理阈值；
- 节点不是聊天消息缩略图、头像菜单或网页预览。

探测日志记录：

```text
节点标签
role
aria-label
title
class
data-* 属性
可见区域尺寸
内部 img/video 数量
内部 button 数量
```

生产逻辑不保存聊天内容，也不输出图片地址。

## 2. 当前活动媒体识别

查看器中可能同时保留上一张、当前张和下一张。

不能使用：

```js
viewer.querySelector('img, video')
```

直接取第一个。

应根据以下条件评分：

- 是否可见；
- 是否位于视口中心；
- 面积是否最大；
- `opacity` 是否大于 0；
- 父节点是否没有隐藏；
- 与查看器中心的距离；
- 视频是否具有活动播放状态。

选出得分最高的媒体作为当前项目。

图片需要同时处理：

```text
load 事件尚未触发
图片已经从缓存加载完成
img.complete 为 true
naturalWidth 大于 0
```

## 3. 上一项／下一项按钮探测

优先收集查看器内所有可点击控件，并记录：

- `aria-label`；
- `title`；
- 按钮在查看器左侧还是右侧；
- 是否禁用；
- 内部 SVG 路径或图标尺寸；
- 点击后当前媒体是否发生变化。

不要仅依赖中文或英文的“下一张”，因为用户可能使用其他界面语言。

推荐判断顺序：

1. 无障碍名称明确表示上一项或下一项；
2. 按钮位于查看器左右边缘；
3. 按钮图标方向；
4. 开发探测模式下人工确认；
5. 点击后媒体身份确实改变。

定位结果应通过函数集中管理：

```text
findMediaViewer()
findActiveMedia()
findPreviousButton()
findNextButton()
findCloseButton()
```

不要让业务控制器直接散落大量选择器。

## 4. 媒体位置探测

按可靠程度依次尝试：

1. 查看器中的官方消息链接；
2. 当前 URL 或 URL 变化；
3. 查看器标题、说明区域内指向消息的链接；
4. 活动媒体祖先节点的 `data-*` 属性；
5. 原始聊天消息节点中的链接；
6. 相册官方计数显示；
7. DOM 活动幻灯片序号。

只有取得稳定值时才保存。

建议生成：

```js
{
  channelKey,
  topicKey,
  messageKey,
  albumIndex,
  targetHref
}
```

其中：

- `channelKey`：优先使用官方消息链接里的稳定频道标识；
- `topicKey`：没有稳定话题标识时使用空字符串；
- `messageKey`：优先消息链接中的数字 ID；
- `albumIndex`：缺失时默认为 0；
- `targetHref`：用于验证能否恢复。

不能确认频道身份时：

- 连续浏览仍可工作；
- 不保存续播位置；
- 不显示恢复入口。

这就是“安全失效”。

## 5. 关闭事件识别

不能只监听关闭按钮，因为用户还可能：

- 按 `Esc`；
- 点击遮罩；
- 浏览器返回；
- 切换账号；
- 页面刷新；
- Telegram 自己销毁查看器。

建议同时使用：

- 查看器节点被移除；
- 查看器变为隐藏；
- 当前活动媒体消失；
- `pagehide`；
- `beforeunload` 作为补偿；
- 已识别关闭按钮的点击事件。

保存操作必须幂等，重复执行不能生成多条记录。

# 四、数据结构

建议将设置和位置分开保存。

```js
{
  version: 1,
  settings: {
    continuousEnabled: false,
    photoDurationMs: 5000,
    panelCollapsed: false
  },
  positions: [
    {
      scopeKey: "account|channel|topic",
      accountKey: "",
      channelKey: "",
      topicKey: "",
      messageKey: "",
      albumIndex: 0,
      targetHref: "",
      updatedAt: 1785000000000
    }
  ]
}
```

## scopeKey

```text
accountKey | channelKey | topicKey
```

Telegram Web A 支持多账号，因此最好加入账号隔离。

但油猴脚本不能凭空读取账号 ID。账号标识必须来自已经确认的页面信息，例如当前用户的官方链接或账号槽位。

如果无法获得可靠账号标识：

- 不保存用户名；
- 不保存昵称；
- 不访问 Telegram 私有存储；
- 账号切换后清空当前恢复上下文；
- 后续再增加账号隔离。

## 存储规则

- 使用 `GM_getValue`／`GM_setValue`；
- 如果 metadata 当前没有对应权限，则保留 metadata 的前提下可先使用 `localStorage`；
- 所有读写包裹在 `try/catch` 中；
- `version !== 1` 时重置；
- 非数组、字段类型异常、时间戳异常的记录直接过滤；
- 同一 `scopeKey` 只保留最新记录；
- 按 `updatedAt` 排序；
- 最多 100 条；
- 写入失败不影响媒体查看器。

# 五、事件流程

```text
脚本启动
  ↓
确认当前域名为 Telegram Web A
  ↓
启动低频 MutationObserver
  ↓
发现媒体查看器
  ↓
创建 ViewerSession
  ↓
识别当前媒体、频道、话题和消息
  ↓
注入 Shadow DOM 控制条
  ↓
读取设置与上次位置
  ↓
绑定当前媒体事件
```

## 图片流程

```text
活动媒体变成图片
  ↓
等待图片完成加载
  ↓
检查连续浏览是否开启
  ↓
检查页面可见、窗口聚焦、未悬停、未缩放、未暂停
  ↓
开始 5 秒定时
  ↓
条件变化 → 取消定时
  ↓
条件恢复 → 从完整 5 秒重新开始
  ↓
到时点击官方下一项
  ↓
等待活动媒体身份改变
```

## 视频流程

```text
活动媒体变成视频
  ↓
重新绑定 ended / play / pause
  ↓
尝试维持 Telegram 自身播放行为
  ↓
用户手动暂停 → 连续控制器暂停推进
  ↓
视频 ended
  ↓
点击官方下一项
```

需要维护内部标志，避免把切换媒体造成的 `pause` 当作用户手动暂停：

```text
isNavigating
isScriptPausing
lastUserMediaInteractionAt
```

## 下一项流程

```text
请求下一项
  ↓
查找官方下一项按钮
  ↓
按钮缺失或禁用 → 停止
  ↓
记录切换前媒体指纹
  ↓
调用 button.click()
  ↓
等待媒体指纹变化
  ↓
成功 → 重新绑定
失败超时 → 再检查一次按钮
  ↓
仍未变化 → 停止并提示
```

媒体指纹可以由本地 DOM 信息组成：

```text
消息 ID + 相册序号
或
媒体元素类型 + 当前显示计数 + DOM 节点身份
```

不要使用媒体 URL作为长期存储字段。

## 关闭流程

```text
查看器关闭
  ↓
停止所有定时器
  ↓
AbortController 解除事件监听
  ↓
保存最后确认的位置
  ↓
移除油猴 UI
  ↓
等待下次查看器打开
```

# 六、“继续上次位置”的现实边界

这是第一版中最难的功能。

## 可以可靠实现的情况

页面能够取得官方消息链接，例如：

```text
https://t.me/频道标识/消息ID
```

并且点击或打开该链接后，Telegram Web A 能定位目标消息。

此时可以：

1. 保存官方目标链接；
2. 下次打开同频道媒体时验证频道一致；
3. 显示“继续上次位置”；
4. 通过官方页面导航定位消息；
5. 再尝试打开对应相册序号。

## 只能降级的情况

历史消息没有出现在当前 DOM 中，且官方消息链接无法直接打开媒体查看器。

油猴脚本此时不能像源码版一样调用：

```text
selectChatMessage
openMediaViewer
searchChatMediaMessages
```

因此不能承诺“点击后一定直接恢复全屏媒体”。

推荐降级为：

```text
跳转到上次消息
```

用户到达消息后，再自动或手动点击媒体。

## 不应采用的方案

不要第一版就尝试：

- 调用页面打包后的私有模块；
- 修改 React／Teact 内部状态；
- 枚举 webpack 模块；
- 从 IndexedDB 读取 Telegram 消息缓存；
- 构造 Telegram 内部 action；
- 拦截 MTProto 数据。

这些方案短期可能成功，但非常容易随 Telegram Web A 更新失效，也违背“安全失效”的设计方向。

# 七、已知风险

### 1. DOM 经常变化

所有定位器必须集中管理，并具有多个候选策略。定位失败时关闭功能，不影响 Telegram。

### 2. 虚拟化渲染

上一张、当前张、下一张可能同时存在。必须判断活动媒体，不能取第一个元素。

### 3. 多语言界面

不能只依赖按钮文字。

### 4. 浏览器自动播放限制

用户开启连续浏览的点击可作为一次用户交互，但后续带声音视频仍可能被浏览器拒绝。

处理方式：

- 不强制取消静音；
- 播放失败时停留；
- 显示“点击播放后继续”；
- 不自动跳过。

### 5. 用户暂停识别

`pause` 可能由用户、媒体切换、浏览器后台或 Telegram 自身触发，需要结合用户交互时间判断。

### 6. 相册序号

官方显示序号与 DOM 幻灯片序号可能不同，必须通过实际页面确认。

### 7. 话题标识缺失

找不到稳定话题 ID 时，只能按频道隔离。不能通过话题标题作为唯一键，因为标题可以重复或修改。

### 8. 下一项尚未加载

点击下一项无反应时，应等待短时间重新探测，不能快速连续点击。

### 9. MutationObserver 性能

只观察必要的子树变化，并对探测函数防抖，不能每次 DOM 变化都扫描整个页面。

### 10. 控件冲突

Shadow DOM 只能隔离样式，不能自动避免布局遮挡。控制条应固定在查看器边缘，并允许折叠或关闭。

# 八、最小验收步骤

## DOM 安全性

1. 在普通聊天页面加载脚本。
2. 不打开媒体查看器。
3. 页面无额外报错、无明显性能下降。
4. Telegram 原有聊天、输入和导航正常。

## 图片连续浏览

1. 进入频道。
2. 打开普通图片。
3. 开启连续浏览。
4. 图片完成加载后等待 5 秒。
5. 确认通过官方下一项操作进入下一张。

## 暂停条件

1. 图片计时期间将鼠标移入媒体区域。
2. 等待超过 5 秒，不能切换。
3. 鼠标移出后重新等待完整 5 秒。
4. 切换浏览器标签页，不能在后台切换。
5. 返回后重新开始完整计时。

## 视频连续播放

1. 打开普通视频。
2. 播放至结束。
3. 确认进入下一项。
4. 手动暂停另一段视频。
5. 确认不会自动跳过。

## 手动切换

1. 连续浏览开启时手动点击下一项。
2. 连续模式保持开启。
3. 新图片重新计时，新视频重新绑定结束事件。

## 队列末尾

1. 到达当前可见媒体末尾。
2. 不循环。
3. 不连续快速点击。
4. 显示“已到当前媒体末尾”。

## 位置记录

1. 在频道 A 打开媒体并切换几项。
2. 关闭查看器。
3. 重新打开频道 A 的另一项媒体。
4. 目标可以定位时显示“继续上次位置”。
5. 进入频道 B 时不显示频道 A 的位置。
6. 相同频道不同话题可识别时互不串用。

## 损坏数据

1. 手动将本地存储改为非法 JSON。
2. 重新加载页面。
3. 脚本自动清理或重置。
4. Telegram 页面仍正常工作。

## 页面升级降级

1. 人为让 DOM 定位器全部匹配失败。
2. 不注入控制条。
3. 不抛出未捕获异常。
4. 不拦截官方上一项、下一项和关闭操作。

# 九、推荐开发顺序

### PR／提交 1：DOM 探测器

```text
chore: 增加 Telegram Web A 媒体查看器 DOM 探测模式
```

只完成：

- 查看器识别；
- 当前媒体识别；
- 上一项／下一项／关闭按钮候选；
- 消息链接和上下文信息探测；
- 调试日志；
- 不执行自动切换。

### PR／提交 2：连续浏览核心

```text
feat: 实现油猴版图片计时与视频结束连续浏览
```

完成：

- Shadow DOM 控制条；
- 图片 5 秒计时；
- 视频 `ended`；
