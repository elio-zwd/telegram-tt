## 2. Task A：扩展脱敏 DOM 探测

目标：在不读取聊天正文和媒体地址的前提下，确认线上 Web K 可用的消息映射证据。

### A1. 查看器结构

- [ ] 探测 `.media-viewer-whole`；
- [ ] 探测官方关闭按钮；
- [ ] 探测作者/日期/消息跳转区域；
- [ ] 探测活动媒体至查看器之间祖先节点的类名和 `data-*` 属性名称；
- [ ] 不输出 `src`、`currentSrc`、频道名、用户名、说明文字。

### A2. 聊天结构

- [ ] 探测当前活动聊天容器；
- [ ] 探测当前消息列表滚动容器；
- [ ] 确认消息节点是否使用 `data-mid`；
- [ ] 确认消息节点是否使用 `data-peer-id`；
- [ ] 确认相册中的媒体点击目标与消息节点关系；
- [ ] 确认同一页面是否同时保留多个隐藏聊天容器。

### A3. 关闭行为

- [ ] 记录官方关闭按钮结构；
- [ ] 确认 `Esc` 后查看器是移除、隐藏还是过渡后移除；
- [ ] 确认关闭动画持续时间范围；
- [ ] 确认 Telegram 是否在关闭后恢复原滚动位置；
- [ ] 确认作者区域或其他官方控件能否跳转当前消息；
- [ ] 只允许人工触发一次验证，不自动循环点击。

### A4. 调试 API

扩展 `TelegramMediaContinuity.inspect()` 或增加专用方法，例如：

```text
inspectMessageMapping()
inspectCloseFlow()
```

- [ ] 结果只含结构、布尔值、类名、属性名称和白名单数字 ID；
- [ ] 不保存或输出聊天正文；
- [ ] 不输出媒体 URL；
- [ ] 调试方法默认不执行点击；
- [ ] 需要执行官方跳转验证时提供明确的单次测试方法；
- [ ] 正式实现完成后删除无用临时探测逻辑，保留有价值的脱敏诊断能力。

## 3. Task B：建立消息目标模型

### B1. 来源消息捕获

- [ ] 在页面捕获阶段监听用户打开媒体的点击；
- [ ] 只处理位于当前活动聊天内的图片或视频点击；
- [ ] 向上寻找高可信消息节点；
- [ ] 记录 `data-mid` 和 `data-peer-id`；
- [ ] 记录相册内媒体序号，仅作辅助信息；
- [ ] 不阻止原事件；
- [ ] 不改变 Telegram 打开媒体行为。

### B2. 查看器消息探测

- [ ] 从查看器公开 DOM、官方链接或经确认属性提取身份；
- [ ] 将来源消息证据与查看器证据做一致性校验；
- [ ] 证据冲突时标记无效，不猜测；
- [ ] 不读取 Telegram 私有运行时对象。

### B3. 目标状态

- [ ] 增加 `pendingMediaTarget`；
- [ ] 增加 `lastConfirmedMediaTarget`；
- [ ] 新媒体只有成功显示后才成为最后位置；
- [ ] 切换超时、加载失败或快速关闭时保留上一项；
- [ ] 相册媒体映射到相册所属消息；
- [ ] 目标状态只存在当前页面内，不新增持久化记录。

## 4. Task C：识别最后成功媒体

### C1. 图片

- [ ] 可见；
- [ ] 当前活动媒体评分最高；
- [ ] `complete === true`；
- [ ] `naturalWidth > 0`；
- [ ] 未触发 `error`；
- [ ] 媒体指纹与切换前不同；
- [ ] 消息身份达到高可信。

### C2. 视频

- [ ] 可见；
- [ ] 当前活动媒体评分最高；
- [ ] `readyState` 或元数据达到可确认状态；
- [ ] 视频错误时不覆盖上一位置；
- [ ] `ended` 自动切换后等待新媒体成功再更新；
- [ ] 循环视频仍保持现有手动切换规则。

### C3. 手动导航

- [ ] TT 控制条上一项、下一项；
- [ ] Telegram 官方上一项、下一项；
- [ ] 键盘方向键由 Telegram 触发的切换；
- [ ] 所有路径统一通过活动媒体变化确认目标；
- [ ] 不根据“点击按钮”直接更新目标。

## 5. Task D：关闭意图与快照

### D1. 官方关闭按钮

- [ ] 捕获但不阻止官方关闭点击；
- [ ] 在官方处理前冻结 `lastConfirmedMediaTarget`；
- [ ] 生成新的 `closeSequenceId`；
- [ ] 同一点击只生成一个关闭任务。

### D2. Esc

- [ ] 只在查看器可见时处理；
- [ ] 不 `preventDefault()`，除非真实页面验证确有必要且不会破坏官方行为；
- [ ] 在官方关闭前冻结目标；
- [ ] 键盘长按或重复事件不会产生多个任务。

### D3. 其他关闭

- [ ] 查看器节点移除或隐藏时作为补偿信号；
- [ ] 如果没有预先捕获到明确关闭意图，但存在最后目标，可执行一次安全定位；
- [ ] 无最后目标时只销毁会话；
- [ ] 页面切换、账号切换或频道切换时取消旧任务。

## 6. Task E：关闭后定位协调器

### E1. 等待查看器关闭

- [ ] 等待节点移除或不可见；
- [ ] 设置明确总超时；
- [ ] 使用 `closeSequenceId` 防止旧任务继续；
- [ ] 不通过固定长延时假定关闭完成；
- [ ] 必要时结合一至两帧 `requestAnimationFrame` 等待布局稳定。

### E2. 目标在 DOM

- [ ] 只在当前活动聊天容器中查找；
- [ ] 优先匹配 `data-peer-id + data-mid`；
- [ ] 没有 `peerId` 时要求当前聊天上下文已确认且 `messageId` 唯一；
- [ ] 找到多个候选时不自动定位；
- [ ] 使用消息所属滚动容器；
- [ ] 滚动到视口中部附近；
- [ ] 避免调用页面根节点滚动。

### E3. 目标不在 DOM

- [ ] 仅在官方跳转控件经过浏览器验证后启用；
- [ ] 每次关闭最多触发一次；
- [ ] 触发后有界等待目标消息进入 DOM；
- [ ] 找到精确目标后居中；
- [ ] 超时停止；
- [ ] 不反复点击或滚动加载历史。

### E4. 防 Telegram 覆盖

- [ ] 第一次定位后短暂检查目标是否仍在合理位置；
- [ ] 只有确认 Telegram 自身恢复滚动覆盖时，允许一次复核定位；
- [ ] 第二次仍失败时停止；
- [ ] 不形成滚动争夺循环。

## 7. Task F：短暂高亮与提示

### F1. 高亮

- [ ] 使用 Web Animations API或临时类；
- [ ] 动画约 1.2 秒；
- [ ] 不覆盖 Telegram 原有永久样式；
- [ ] 节点移除时安全结束；
- [ ] 重复定位先清理旧动画。

### F2. 提示

- [ ] 目标未加载：`最后查看消息当前未加载`；
- [ ] 映射不确定：`无法确认媒体所属消息，已正常关闭`；
- [ ] 目标可能删除：`目标消息可能已删除`；
- [ ] 提示自动消失；
- [ ] 不遮挡输入框、消息操作或 Telegram 顶部栏。
