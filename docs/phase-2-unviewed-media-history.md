# 第二阶段：只浏览未看过的媒体

## 功能目标

为频道连续媒体浏览增加本地浏览记录，使后续版本可以提供：

> 只浏览未看过的媒体

本分支先实现独立数据层，不修改第一版的媒体查看器、连续浏览控制条、自动切换和自动保存流程。

## 本分支范围

新增：

```text
src/util/channelMediaViewHistory.ts
```

数据层支持：

- 按 Telegram 账号隔离；
- 按频道隔离；
- 按话题 / Thread 隔离；
- 相册中的每个媒体序号独立记录；
- 判断单个媒体是否看过；
- 从任意媒体数组中过滤出未看过项目；
- 单个或批量标记为已看；
- 将单个媒体重新标记为未看；
- 清理单个话题、整个频道、整个账号或全部记录；
- 自动去重和修复损坏数据；
- LocalStorage 异常时安全降级。

## 媒体身份

浏览记录使用以下字段确定唯一媒体：

```text
账号 ID + 频道 ID + Thread ID + 消息 ID + 相册媒体序号
```

这意味着：

- 不同账号的记录互不影响；
- 同一频道不同话题互不影响；
- 同一相册里的每张图片或视频分别计算；
- 普通单媒体消息的媒体序号为 `0`。

## 记录时机

后续接入媒体查看器时，应仅在媒体真正成为当前活动项后记录。

建议条件：

1. 当前项目是频道中的普通消息媒体；
2. 媒体已经成功显示或视频已经具备可播放状态；
3. 当前项目不是左右两侧的预加载页；
4. 当前项目不是头像、广告、网页区块或独立媒体数组；
5. 用户仍处于当前账号和频道。

无论用户是否开启连续浏览，只要媒体真正成为当前项，都可以记录为已看。这样“只浏览未看过”反映的是用户的实际媒体浏览历史，而不是单次自动播放队列历史。

以下情况不应记录：

- 仅完成预加载但没有成为当前项；
- 加载失败并被跳过；
- 用户快速划过且媒体尚未成功展示；
- 无权访问或未解锁的付费媒体；
- 广告、头像和网页预览媒体。

## 队列过滤规则

第一版稳定后，可以在连续浏览设置中增加：

```text
只浏览未看过的媒体
```

开启后：

1. 用户主动点击打开的当前媒体仍然正常显示；
2. 查找下一项时跳过已有浏览记录的媒体；
3. 相册中只跳过已看过的具体媒体序号；
4. 已加载队列全部看过时，继续触发频道媒体动态加载；
5. 确认没有更多未看媒体后停止，并显示“没有更多未看媒体”；
6. 不应因为连续跳过已看项目而触发图片计时或自动保存；
7. 手动点击上一项或下一项时，可按产品设置决定是否仍应用未看过滤。

推荐默认行为：自动推进应用未看过滤，用户手动方向键仍允许查看已看媒体，避免用户无法返回上一项。

## 数据容量

存储键：

```text
tt.channelMediaViewHistory.v1
```

最多保留：

```text
20,000 个媒体记录
```

达到上限后淘汰最旧记录。被淘汰的旧媒体未来可能再次被视为“未看过”，这是控制 LocalStorage 大小的预期折中。

记录只保存在当前设备的浏览器或桌面客户端本地，不上传服务器，也不在设备间同步。

## 损坏数据处理

读取时会自动处理：

- JSON 无法解析：删除整份损坏记录；
- 存储版本不兼容：删除旧版本记录；
- 单条字段非法：过滤该条；
- 同一媒体重复记录：只保留最新记录；
- 超过容量：保留最新 20,000 条；
- LocalStorage 不可访问或写入失败：返回失败状态，但不阻断媒体查看。

## 后续接入建议

### 1. 设置模型

在第一版 `ContinuousMediaSettings` 中增加持久化字段：

```ts
shouldOnlyShowUnviewed: boolean;
```

默认值建议为 `false`。

### 2. 设置界面

在“设置 → 数据与存储 → 连续媒体浏览”增加：

- 只浏览未看过的媒体；
- 清除全部媒体浏览记录。

后续每频道独立设置接入后，还可以在频道菜单中增加：

- 当前频道只浏览未看过；
- 将当前频道全部标记为未看。

### 3. 当前媒体记录

推荐在 `MediaViewerSlides` 确认中间活动页切换完成，并且媒体已准备好时调用：

```ts
markChannelMediaViewed({
  accountId: currentUserId,
  chatId: message.chatId,
  threadId,
  messageId: message.id,
  mediaIndex: item.mediaIndex,
});
```

不要在左右预加载页、候选队列生成阶段或下载开始阶段调用。

### 4. 下一项选择

推荐在连续模式的下一项候选查找中增加可选跳过逻辑，而不是提前重建一份巨大队列：

1. 使用现有 `getNextItem` 获取候选；
2. 检查媒体类型筛选；
3. 检查内容保护和访问状态；
4. 开启未看过滤时检查 `isChannelMediaViewed`；
5. 不匹配则继续查找下一个候选；
6. 接近已加载边界时沿用现有动态加载。

需要设置最大同步跳过次数，避免异常数据造成长时间主线程循环；超过当前已加载项目数量后应进入动态加载或结束判断。

## 手工验收场景

接入 UI 和队列后至少验证：

1. 查看普通图片后关闭并重新打开队列，该图片被跳过；
2. 查看视频后，即使未播放到结尾，只要媒体已成功成为当前项，也按规则标记；
3. 相册只看第二张时，仅第二张被过滤；
4. 预加载的下一张没有实际打开时仍属于未看；
5. 加载失败项目不记为已看；
6. 不同频道、话题和账号记录互不串用；
7. 已加载媒体全部看过时继续加载历史，而不是立即错误结束；
8. 清除当前频道记录后，该频道媒体重新进入未看队列；
9. 关闭“只浏览未看过”后，所有媒体恢复正常浏览；
10. LocalStorage 被禁止时，媒体查看功能仍正常运行。

## 完整接入状态

- 连续浏览控制条增加眼睛按钮，默认关闭“只浏览未看过”。
- “设置 → 数据与存储”提供同一默认开关和清除当前账号浏览记录入口。

- 频道媒体成为活动项并完成加载后写入本地浏览记录。
- 相册媒体按 `messageId + mediaIndex` 分别记录。
- 预加载、加载失败、受保护媒体和非频道媒体不会写入记录。
- 媒体切换保留 `threadId`，确保话题记录不会错误归入主话题。
