# Telegram Web K 插件优先开发路线

## 0. 文档定位

本文件是 Telegram Web K 油猴插件的唯一高层路线摘要。详细实施规则见：

- `docs/tampermonkey-web-k-post-v1-plan.md`
- `docs/tampermonkey-web-k-post-v1-tasks.md`
- `docs/tampermonkey-web-k-post-v1-handoff.md`

后续只开发：

```text
https://web.telegram.org/k/*
```

Web A 脚本和 Telegram 桌面源码保持历史只读，不参与新功能开发、验收或合并。

## 2. 已完成能力

当前稳定实现至少包括：

- 图片按预设或 `1.0～300.0` 秒自定义时间自动切换；
- 普通视频在有效 `ended` 后自动切换；
- 循环媒体按 `HTMLVideoElement && loop === true` 识别并定时切换；
- 正向和反向连续浏览；
- 图片／视频筛选；
- Space 暂停／继续、A 开启／关闭及输入区域隔离；
- 全屏、标准 PiP、离线、缓冲、自动播放限制和失败保护；
- 普通视频静音、音量和倍速偏好；
- 关闭查看器后定位最后真正成功显示的媒体消息；
- 相册按消息与媒体序号映射；
- 同频道跨 viewer 队列自动续流；
- 正向加载更新媒体、反向加载更旧历史媒体；
- 无更多媒体时保持连续浏览开关开启并安全暂停；
- 用户点击、按键、频道／话题切换时取消旧 continuation operation；
- Shadow DOM 控制条、窄窗口换行、收起／展开和脱敏调试。

旧能力“队列末尾停止”已被 PR #21 替代。当前行为是：

```text
viewer 队列存在下一项
→ 使用官方导航

viewer 队列耗尽
→ 关闭当前 viewer
→ 在同频道公开 DOM 中有界加载
→ 精确打开相邻媒体

未找到更多媒体或超过上限
→ 保持 continuousEnabled = true
→ 安全暂停，不无限滚动
```

不得将多个主要目标合并成一个开发 PR。每个实现 Task 必须遵守：

```text
一个对话
一个分支
一个明确任务
一个 Draft PR
```

同一个 AI 可以在前一个 PR 完成后串行接手下一个任务，但一个对话不得同时维护多个分支或 PR。

## 4. P2：状态、频道与本地数据

| Task | 优先级 | 目标 | 关键门禁 |
| --- | --- | --- | --- |
| P2-01 | Must | 版本化本地数据容器、迁移、损坏修复、容量和清理规则 | 不增加用户可见功能；兼容 `tt.mediaContinuity.v1` |
| P2-02 | Must / Research | 冻结账号、频道、话题、消息、相册索引和媒体类型身份 | 仅公开 DOM；身份不可靠时禁止猜测 |
| UI-01 | Must | 在已确认设计基础上实现新悬浮 UI | 不混入位置、历史、收藏、下载等业务 |
| P2-03 | Must | 用户主动“继续上次位置”，支持相册索引 | 不进入频道即强制打开；目标失效安全提示 |
| P2-04 | Should | 全局默认 + 频道／话题字段级覆盖 | 支持恢复全局默认 |
| P2-05 | Must | 成功显示后记录有界浏览历史 | 不记录正文、媒体 URL、标题或用户名 |
| P2-06 | Should | 自动浏览只跳过已看媒体 | 手动导航仍可查看；有界加载，不无限滚动 |
| P2-07 | Should | 用户主动收藏／稍后查看 | 只保存匿名稳定身份，不保存媒体内容 |
| P2-08 | Must | 版本化 JSON 导入、导出和分级清理 | 导入前校验，明确隐私风险 |

P2 编码前必须先冻结：

- Schema 版本和迁移策略；
- 账号、频道、话题和媒体身份可靠性；
- 记录上限、淘汰和清理规则；
- 目标失效和虚拟列表回收时的降级；
- 不包含正文、媒体 URL 和可读名称的隐私边界。

## 5. UI 设计协作边界

另一个独立对话负责：

```text
UI-DESIGN：视觉与交互讨论，不写代码
```

本路线只定义：

```text
UI-01：设计确认后的独立实现 PR
```

UI-01 的依赖顺序：

```text
P2-01
→ P2-02
→ UI-DESIGN 已确认
→ UI-01
→ P2-03
```

本规划不决定最终视觉风格，不生成 UI 图片，不修改控制面板代码，也不假设设计已经确认。

新 UI 必须预留以下业务插槽：

- 高频播放控制区；
- 状态区；
- 二级设置区；
- 频道操作入口；
- 数据管理入口；
- 错误、暂停和续流状态；
- 后续恢复位置、未看模式和收藏入口。

UI-01 只实现信息架构、组件壳、现有功能迁移和业务插槽。不得在同一 PR 中实现每频道位置、浏览历史、收藏或下载。

## 6. P3：保存与下载

D01 是强制门禁，必须在真实 Telegram Web K 页面确认：

- 官方下载入口；
- 图片、普通视频和循环媒体行为；
- URL 生命周期；
- 下载开始、完成和失败是否可观察；
- 文件名可控程度；
- 浏览器多文件下载提示；
- 内容保护、付费和无权限内容；
- 是否能在不使用私有 API 的前提下可靠实现。

D01 未通过时：

- 不开发自动保存；
- 不开发下载队列；
- 不承诺文件名、目录和限速控制；
- 将不可行项标记为 `Cancelled` 或保留为 `Research`。

P3 顺序固定为：

```text
D01 研究
→ D02 手动保存
→ D03 文件名模板
→ D04 下载记录与去重
→ D05 队列、取消和有限重试
→ D06 浏览时自动保存
→ D07 类型与限额
→ D08 目录与限速实验
```

## 7. P4：高级实验

P4 不属于承诺交付范围，只分别记录：

- 当前会话队列循环；
- 前台有界等待新媒体；
- 下一项预加载研究；
- 可见范围序号和总数；
- 日期起点研究；
- 随机浏览；
- 多频道队列。

PR #21 已部分完成“动态加载更多”：

```text
已完成：
同频道、正向／反向、有界加载、关闭并重新打开媒体。

未完成：
完整频道枚举、无限历史队列、跨频道队列、后台持续等待。
```

不得承诺桌面客户端级完整媒体数据库、无限滚动、后台永久运行或跨频道无界队列。

## 9. 安全与隐私边界

始终禁止：

- Telegram API、Bot API、MTProto；
- Telegram 私有 webpack 对象或内部运行时；
- Telegram IndexedDB 账号、认证或缓存数据；
- 保存聊天正文、媒体 URL、标题、用户名或可读频道名称到行为数据；
- 绕过内容保护、付费媒体或权限限制；
- 无限滚动、无上限历史抓取或无限点击；
- 一键下载整个频道；
- 浏览器关闭后的永久运行；
- Web A 新功能。

## 10. 路线维护规则

每个 PR 合并后更新：

- 状态、Base、Head、Commit 和 PR；
- 实际修改模块；
- 静态、CI 和真实浏览器验证；
- 未验证内容；
- 已知风险和回滚；
- 下一依赖；
- 是否允许并行。

路线只记录真实状态，不把计划、研究或旧桌面源码能力写成 Web K 已完成。
