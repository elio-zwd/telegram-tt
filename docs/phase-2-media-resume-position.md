# 第二阶段：频道媒体续播位置

## 功能目标

用户退出媒体查看器后，客户端记住该账号在当前频道或话题中最后浏览的媒体位置。之后从同一频道重新打开其他媒体时，如果上次位置仍在本地消息缓存中，媒体查看器提供“继续上次位置”入口。

本功能不依赖连续播放控制器，也不修改图片倒计时、视频结束切换或自动保存主链路，可与第一阶段并行开发。

## 当前实现

### 位置记录

关闭媒体查看器时记录：

- 当前 Telegram 账号 ID；
- 聊天或频道 ID；
- 话题 / Thread ID；
- 消息 ID；
- 相册内媒体序号；
- 最后更新时间。

以下查看场景不会保存为续播位置：

- 头像查看器；
- 广告媒体；
- 独立媒体数组；
- 网页区块媒体。

### 恢复入口

当以下条件同时满足时显示入口：

- 当前查看项是普通消息媒体；
- 当前账号、频道和话题存在历史位置；
- 历史位置与当前媒体不同；
- 历史消息仍存在于本地消息缓存。

桌面端在媒体查看器操作区显示播放图标按钮；移动端在“更多操作”菜单中显示“继续上次位置”。

点击后重新打开历史消息及其相册媒体序号。

### 本地存储策略

存储键：

```text
tt.mediaViewerResume.v1
```

策略：

- 按账号、频道、话题隔离；
- 同一键只保留最新位置；
- 最多保留 100 条；
- 超过上限时淘汰最旧记录；
- JSON 损坏或版本不兼容时自动清理；
- 单条非法记录会被过滤并重写；
- LocalStorage 不可用或配额异常时静默降级，不阻断媒体查看。

## 手工验收

1. 登录账号 A，进入频道 X，打开一张图片。
2. 手动切换到另一条媒体或相册中的其他媒体。
3. 关闭媒体查看器。
4. 在频道 X 中打开另一张媒体。
5. 确认桌面端操作区或移动端更多菜单出现“继续上次位置”。
6. 点击入口，确认返回步骤 2 关闭前的位置。
7. 在另一频道、另一话题或账号 B 中重复，确认位置互不串用。
8. 清空浏览器站点存储后确认入口消失，媒体查看器仍可正常使用。

## 已知边界

- 历史消息未在本地消息缓存中时暂不显示恢复入口，避免打开空白查看器。
- 当前版本记录媒体位置，不记录视频播放到第几秒。
- 当前版本提供底层单条及全部清除 API，设置页中的可视化“清除续播记录”入口留待后续小任务。
- 第一阶段分支合并后，需要重点检查 `MediaViewerActions.tsx` 与媒体查看器操作区的冲突。
