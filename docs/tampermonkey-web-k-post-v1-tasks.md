# Telegram Web K V1 后 P2–P4 Task 清单

## 1. 使用规则

本文件只描述计划，不代表功能已经实现。状态标签：

```text
Must：核心路线
Should：建议交付
Optional：可选
Research：必须先研究
Deferred：暂缓
Cancelled：取消
```

所有实现 Task 必须遵守：

```text
一个对话
一个分支
一个明确任务
一个 Draft PR
```

规划基线为：

```text
codex/tampermonkey-media-continuity@51a89ebdb4b609023176ee8b1dfdb8dfcacb7377
版本：0.4.0-k11
```

每个 Task 启动时仍须重新核验最新稳定 Base、开放 PR、目标文件和 CI 状态。

### P2-01：本地数据 Schema V2

- **Task ID**：P2-01
- **功能名称**：本地数据 Schema V2
- **分类**：Must
- **目标**：建立版本化本地数据容器、迁移、损坏修复、容量、淘汰和清理基础。
- **用户价值**：让后续位置、设置、历史、收藏和下载记录安全共存并可升级。
- **前置依赖**：PLAN-01。
- **建议分支**：`feat/tampermonkey-web-k-storage-schema`
- **建议 PR 标题**：`feat: 建立 Web K 本地数据 Schema V2`
- **预计修改模块**：`core/settings.js` 或独立 storage 模块、verifier、文档、版本和生成 userscript。
- **明确不修改范围**：不增加用户可见功能，不实现频道身份、位置、历史、收藏或下载。
- **数据模型**：`schemaVersion/metadata/globalSettings/channelPositions/channelOverrides/viewHistory/bookmarks/downloadRecords`；兼容 `tt.mediaContinuity.v1`。
- **状态机或流程**：读取 → 解析 → 识别版本 → 迁移/规范化 → 分区修复 → 原子写入 → 配额失败回退。
- **产品规则**：现有设置必须保留；单分区损坏不清空全部；所有集合必须有上限。
- **失败和降级行为**：未知版本或写入失败时返回安全默认并保留可回滚数据，不阻断 Telegram。
- **隐私边界**：不保存 DOM、正文、URL、标题、用户名或频道可读名称。
- **静态验证**：旧 v1、损坏 JSON、未知版本、部分损坏、配额、上限、淘汰和清理。
- **真实浏览器验收矩阵**：旧设置升级、刷新、localStorage 禁用/满额、异常中断和回退。
- **CI 要求**：Linux／Windows build/verifier、双构建一致性和真实浏览器迁移验收。
- **已知风险**：迁移丢设置、频繁写入和配额不足。
- **回滚方案**：旧版本继续读取 v1 设置；新分区可被忽略，不自动删除旧数据。
- **本地只读验收 Prompt 要点**：重点检查迁移前后值、损坏隔离、无新 UI、无第二套互斥数据源和生成一致性。

### P2-02：频道／话题／媒体身份契约

- **Task ID**：P2-02
- **功能名称**：频道／话题／媒体身份契约
- **分类**：Must / Research
- **目标**：用真实 Web K 公开 DOM 证据冻结 `accountKey/peerKey/topicKey/messageKey/albumIndex/mediaType`。
- **用户价值**：防止跨账号、跨频道、跨话题串数据和恢复到错误媒体。
- **前置依赖**：P2-01。
- **建议分支**：`research/tampermonkey-web-k-identity-contract`
- **建议 PR 标题**：`research: 冻结 Web K 频道与媒体身份契约`
- **预计修改模块**：研究文档；证据充分时可增加最小 `platform/identity` 封装，但不得实现业务功能。
- **明确不修改范围**：禁止 Telegram API、Bot API、MTProto、webpack 私有对象、IndexedDB 和业务 UI。
- **数据模型**：逐字段来源、可靠性等级、生命周期、序列化和缺失规则。
- **状态机或流程**：真实页面采样 → 节点替换/虚拟列表/频道话题切换 → 证据评级 → PASS/PASS WITH LIMITS/FAIL。
- **产品规则**：身份缺失不猜测；话题不可靠时不得混入主频道；账号不可靠时禁止跨账号复用。
- **失败和降级行为**：字段冲突或缺失时禁用对应持久化能力，只保留全局设置和现有浏览。
- **隐私边界**：研究只提交脱敏别名、属性名称和结构，不提交真实 ID、正文或 URL。
- **静态验证**：公开来源、稳定性、降级、序列化、冲突和禁用私有接口。
- **真实浏览器验收矩阵**：多账号槽位、频道、群组、话题、相册、刷新、节点替换、虚拟列表回收和切换。
- **CI 要求**：纯研究不要求构建；若加平台封装则完整 Linux／Windows CI。
- **已知风险**：账号和话题公开身份不足，Telegram DOM 变化。
- **回滚方案**：仅回滚研究/封装；不迁移业务数据。
- **本地只读验收 Prompt 要点**：复现实验、区分事实与假设、确认所有字段缺失时安全降级且无私有 API。

- 本地只读验收与远端开发，但验收不得修改分支。
