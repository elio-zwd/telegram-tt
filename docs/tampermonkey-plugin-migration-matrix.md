# Telegram TT 插件优先迁移矩阵

## 1. 目的

产品路线调整为：

> 优先通过 Tampermonkey 油猴插件实现原计划中的 Telegram 桌面版二次开发需求。

本矩阵用于：

- 区分仓库中真实存在的原桌面版需求与后续建议功能；
- 判断 Web A / Web K 的插件可行性；
- 明确隐私、安全、DOM 稳定性和浏览器能力边界；
- 拆成独立分支、独立 PR；
- 支持用户手动开启多个 AI 对话，同时避免修改范围重叠。

本矩阵是规划，不代表所有功能已经实现或验证。

## 3. 判定说明

### 3.1 插件是否可实现

- **完全可实现**：只依赖公开 DOM、浏览器事件和本地存储，可以安全失效；
- **部分可实现**：浏览器、虚拟列表、权限或 DOM 限制导致无法达到桌面源码级能力；
- **不可实现**：在当前约束下无法可靠完成，或必须依赖私有接口、系统能力或绕过权限；
- **需要实验**：理论可行，但必须先通过真实页面和浏览器行为验证。

### 3.2 来源标签

- **原计划**：仓库桌面版需求文档明确存在；
- **当前新增需求**：用户在油猴路线中明确提出，但旧桌面文档没有同名需求；
- **建议功能**：本轮规划建议，不能标成原计划。

## 5. 明确不可迁移或不应实现

根据原计划第 15 章和当前油猴约束，以下不纳入插件开发：

| 功能 | 结论 | 原因 |
| --- | --- | --- |
| 一键下载整个频道 | 不实现 | 会变成无边界批量下载器，风险和资源消耗过高 |
| 无上限后台爬取历史媒体 | 不实现 | 依赖大量加载和可能的私有接口，不符合安全失效 |
| 绕过禁止保存保护 | 禁止 | 违反权限和产品约束 |
| 未解锁付费媒体预加载或保存 | 禁止 | 违反权限约束 |
| 自动转发媒体 | 不实现 | 不属于观看核心，涉及外部写入 |
| 云端媒体备份 | 不实现 | 违反本地数据原则 |
| 自动删除 Telegram 原消息 | 不实现 | 高风险写操作，与产品目标无关 |
| 读取 Telegram 私有 IndexedDB/打包模块 | 禁止 | 页面升级脆弱，超出公开 DOM 范围 |
| 移动端后台长时间下载 | 不承诺 | 浏览器和系统后台限制 |

## 6. 推荐实施顺序

### 阶段 P0：完成核心闭环

1. Web K 关闭后定位最后媒体消息；
2. 形成稳定的 Web K 消息映射能力；
3. 保持现有连续浏览回归通过。

### 阶段 P1：增强观看体验

建议顺序：

1. Web A 关闭后定位最后媒体消息；
2. Web A/K 消息映射行为对齐；
3. 媒体类型过滤；
4. 快捷键；

## 10. 风险总览

### 10.1 DOM 风险

最高风险区域：

- 消息节点身份；
- 虚拟列表；
- 官方消息跳转；
- 下载控件；
- 相册序号；
- 付费和受保护媒体。

所有定位器必须集中、可探测、可安全失效。

### 10.2 隐私风险

本地记录只允许包含完成业务所需的最小身份字段：

- 账号槽位或匿名账号键；
- 频道键；
- 话题键；
- 消息 ID；
- 相册序号；
- 时间戳；
- 设置项。

默认不得保存：

- 聊天正文；
- 媒体 URL；
- 联系人或频道显示名称；
- 用户名；
- 账号手机号；
- 未经用户开启的浏览统计。

### 10.3 浏览器限制

油猴插件不能等同桌面应用：

- 下载目录控制有限；
- 后台长期运行不可靠；
- 浏览器自动播放有限制；
- 文件大小和下载完成状态可能不可见；
- 虚拟列表历史加载由 Telegram 控制。

产品文案和验收条件必须反映这些边界。

## 11. 维护规则

- 一个任务、一个分支、一个 PR；
- 新功能开始前检查开放 PR；
- 多对话通过 GitHub 文档和 PR 交接；
- 不直接修改默认分支；
- 不未经用户授权合并；
- 不把建议功能写成原计划；
- 不把静态分析写成浏览器验收；
- 不因为页面源码存在某类名就假定线上 DOM 一致；
- Telegram DOM 变化时宁可停止功能，也不能错误点击或错误滚动。
