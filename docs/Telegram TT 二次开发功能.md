# Telegram TT 二次开发功能定义

## 一、产品定位

在现有 Telegram Web A 客户端基础上，增加一个面向频道媒体的：

> **频道连续媒体浏览模式**

用户进入频道并打开任意图片或视频后，可以像观看媒体流一样，自动浏览后续图片、自动播放视频，并可选择是否将实际浏览到的媒体保存到本地。

第一阶段不把产品做成“频道批量下载器”，而是做成：

- 以观看为核心；
- 以当前频道为范围；
- 以当前打开的媒体为起点；
- 用户始终可以暂停、跳过或退出；
- 自动保存默认关闭；
- 不在后台无边界下载整个频道。

## 二、核心使用流程

1. 用户进入一个频道。
2. 点击频道消息中的图片或视频。
3. 打开现有全屏媒体查看器。
4. 查看器顶部或底部提供“连续浏览”按钮。
5. 用户开启连续浏览后：
   - 图片显示指定时间后自动切换；
   - 视频播放结束后自动切换；
   - 下一项是视频时自动开始播放；
   - 下一项仍未加载时显示缓冲状态；
   - 无法加载的媒体按照错误策略跳过。
6. 用户关闭连续浏览或退出媒体查看器后，本次连续浏览结束。

## 三、连续浏览范围

### 3.1 默认范围

默认只浏览：

- 当前频道；
- 当前话题或消息列表；
- 从用户点击的媒体开始；
- 当前媒体之后的图片和视频。

不自动跨越到其他频道、私聊或群组。

### 3.2 媒体类型筛选

用户可以选择：

- 图片和视频；
- 仅图片；
- 仅视频。

第一版默认选择“图片和视频”。

以下内容第一版不进入连续队列：

- 普通文件；
- 音频和语音；
- 贴纸；
- 视频通话和直播；
- 频道头像；
- 网页预览图片；
- 广告媒体；
- 无权访问的付费媒体；
- 受保护且禁止保存或转发的媒体。

GIF 可以作为独立选项处理，默认按照图片计时切换，不等待其无限循环结束。

### 3.3 相册消息

一条消息中包含多张图片或多个视频时：

1. 先按照相册内部顺序浏览完；
2. 再进入下一条包含媒体的频道消息。

相册中的每个媒体都计为一个独立项目，例如显示为“12 / 86”。

### 3.4 浏览方向

提供两种顺序：

- 按频道消息顺序继续浏览；
- 反向浏览历史媒体。

默认沿着用户当前点击“下一张”时的现有方向继续，避免自动模式和手动方向产生相反结果。

### 3.5 队列末尾行为

提供：

- 播放完停止；
- 等待频道新媒体；
- 从本次队列开头循环。

第一版默认“播放完停止”，不自动循环，以免用户离开后长时间重复播放。

## 四、图片自动切换

### 4.1 图片停留时间

用户可以配置：

- 2 秒；
- 3 秒；
- 5 秒；
- 8 秒；
- 10 秒；
- 15 秒；
- 30 秒；
- 自定义时间。

默认建议为 5 秒。

### 4.2 计时开始条件

图片满足以下条件后才开始计时：

- 原图或可接受清晰度的预览已经加载；
- 当前图片处于活动页面；
- 媒体查看器没有被隐藏；
- 用户没有暂停连续浏览。

加载时间不计入图片停留时间。

### 4.3 自动暂停条件

出现以下操作时暂停图片倒计时：

- 用户正在缩放图片；
- 用户正在拖动图片；
- 用户打开更多操作菜单；
- 用户正在查看长说明文字；
- 浏览器标签页进入后台；
- 应用窗口最小化；
- 网络断开；
- 用户手动暂停。

恢复后重新开始本张图片的完整计时，避免用户回来时立即被切走。

## 五、视频连续播放

### 5.1 普通视频

普通视频的行为：

1. 进入当前项后自动播放；
2. 播放结束后自动切换下一项；
3. 下一项是视频时继续播放；
4. 下一项是图片时启动图片倒计时。

当前播放器的视频结束事件只会重置播放状态；连续模式开启后，需要把结束事件交给连续浏览控制器。

### 5.2 短视频循环

现有播放器会让 GIF 或时长不超过一定范围的短视频循环播放。

连续模式下建议调整为：

- GIF：播放指定时间后切换；
- 普通短视频：默认只播放一次后切换；
- 用户可开启“短视频循环一次”；
- 不允许短视频无限循环阻断整个队列。

### 5.3 声音策略

提供：

- 延续上一条视频的静音状态；
- 延续当前媒体查看器音量；
- 新视频默认静音。

默认延续用户上一次设置。

因为浏览器可能限制未经交互的有声自动播放，当自动播放失败时：

- 视频保持暂停；
- 显示“点击继续播放”；
- 不直接跳过；
- 用户完成一次播放操作后继续后续连播。

### 5.4 视频手动操作

用户拖动视频进度、调整倍速或暂停时：

- 不触发自动切换；
- 只有视频真正播放到结尾才切换；
- 手动点击“下一项”时立即停止当前视频；
- 已播放进度不需要跨会话保存，后续版本再考虑。

### 5.5 画中画与全屏

视频进入画中画或系统全屏时：

- 自动切换暂时停止；
- 视频播放结束后停留在当前项；
- 用户退出画中画或全屏后，再询问或继续进入下一项。

第一版不在画中画状态下静默切换到另一个媒体。

## 六、连续浏览控制界面

媒体查看器增加一个简洁控制条：

- 连续浏览：开启/关闭；
- 暂停/继续；
- 上一项；
- 下一项；
- 当前序号和总数；
- 图片剩余时间；
- 自动保存状态；
- 媒体类型筛选；
- 更多设置。

### 推荐交互

- `Space`：暂停或继续；
- `←`：上一项；
- `→`：下一项；
- `Esc`：退出；
- `A`：开启或关闭连续浏览；
- `D`：切换当前媒体是否保存。

键盘快捷键不应影响用户在输入框中的正常输入。

用户手动切换到下一项后：

- 连续浏览保持开启；
- 新媒体重新开始计时或播放；
- 不需要重新点击开始。

## 七、下一项预加载

为了减少切换时等待，连续模式开启后可以：

- 加载当前媒体；
- 预加载下一项；
- 可选预加载下两项；
- 不批量加载整个频道。

第一版建议固定预加载下一项，不开放复杂配置。

### 网络较差时

- 当前媒体正常展示；
- 下一项显示预加载进度；
- 超过设定时间仍无法加载时显示重试；
- 可以自动跳过失败项；
- 连续失败达到 3 项时暂停连续浏览，并提示检查网络。

## 八、自动保存到本地

## 8.1 功能命名

界面中使用：

> **浏览时自动保存**

不要继续使用“自动下载”，避免和现有自动加载缓存设置混淆。

## 8.2 保存模式

提供三个模式：

1. **关闭**
   - 只播放或显示；
   - 不主动保存到系统下载目录。
2. **保存实际浏览的媒体**
   - 媒体真正成为当前项后才保存；
   - 用户快速跳过但没有完整打开的项目不保存；
   - 推荐作为第一版唯一的自动保存模式。
3. **保存预加载媒体**
   - 当前项和下一项一起保存；
   - 可能产生用户没有实际观看的文件；
   - 放到后续版本。

默认关闭。

## 8.3 类型设置

分别配置：

- 自动保存图片；
- 自动保存视频；
- 自动保存 GIF。

示例：

- 图片：开启；
- 视频：开启；
- GIF：关闭。

## 8.4 文件大小限制

分别设置：

- 图片最大尺寸；
- 视频最大尺寸；
- 单个文件最大尺寸；
- 单次连续浏览最大保存量。

建议第一版默认：

- 图片不单独限制；
- 视频最大 200 MB；
- 单次会话最大保存 2 GB；
- 达到限制后停止自动保存，但继续浏览。

## 8.5 下载触发时机

媒体满足以下条件后才加入保存任务：

- 已成为当前活动媒体；
- 用户有权访问；
- 媒体不受保存保护；
- 符合类型筛选；
- 符合大小限制；
- 本地不存在相同媒体；
- 自动保存仍处于开启状态。

连续浏览关闭后：

- 已经开始的当前下载可以继续；
- 尚未开始的排队任务全部取消；
- 不继续加载新的媒体。

## 8.6 重复文件处理

优先使用 Telegram 媒体唯一标识或媒体哈希判断重复。

出现重复时默认：

- 跳过重复文件；
- 不生成 `文件名 (1)`；
- 在下载记录中标记“已存在”。

用户仍可对单个媒体手动执行“另存为”。

## 8.7 文件命名

默认命名格式：

```
频道名称_发布日期_消息ID_媒体序号.扩展名
```

例如：

```
ChannelName_2026-07-25_1582_02.mp4
```

文件名应处理：

- Windows 非法字符；
- 过长频道名称；
- 重复名称；
- 缺失扩展名；
- 原始文件名不可信的情况。

## 8.8 目录结构

桌面端建议允许：

- 统一保存目录；
- 按频道建立子目录；
- 按日期建立子目录。

推荐默认结构：

```
TelegramTT Downloads/频道名称/年月/
```

Web 版继续使用浏览器下载机制；Tauri 桌面版提供固定下载目录和更稳定的自动保存能力。

## 8.9 下载状态

提供一个小型下载状态入口：

- 等待中；
- 下载中；
- 已完成；
- 已跳过；
- 已取消；
- 下载失败；
- 磁盘空间不足。

失败任务允许手动重试，但不因为一个下载失败而阻断媒体浏览。

## 九、全局设置与频道独立设置

### 全局设置

在“设置 → 数据与存储”中新增“连续媒体浏览”区域：

- 默认是否开启连续浏览；
- 默认图片停留时间；
- 默认媒体类型；
- 默认浏览方向；
- 是否预加载下一项；
- 浏览时自动保存；
- 保存类型；
- 文件大小限制；
- 下载目录；
- 队列结束行为。

### 当前频道设置

频道菜单中提供：

> 连续浏览设置

可覆盖全局设置，例如：

- 这个频道只看图片；
- 这个频道图片显示 8 秒；
- 这个频道允许自动保存；
- 这个频道不自动保存视频。

第一版可以先只有全局设置，频道独立设置放入第二阶段。

## 十、状态保存

建议持久化：

- 连续浏览默认开关；
- 图片停留时间；
- 类型筛选；
- 自动保存开关；
- 保存类型；
- 视频音量；
- 视频倍速；
- 浏览方向。

本次媒体会话结束后不保存：

- 临时队列；
- 当前计时进度；
- 下载失败的临时重试次数；
- 当前缩放比例。

“记住上次看到的位置”作为后续可选功能，不在第一版默认启用。

## 十一、权限与隐私规则

必须遵守：

- 受保护频道或禁止保存的媒体不能自动保存；
- 没有访问权限的媒体不能加入队列；
- 付费媒体未解锁前不能预加载原文件；
- 不绕过 Telegram 的内容保护；
- 不把媒体上传到其他服务器；
- 浏览记录和下载记录默认只保存在本地；
- 退出账号时允许清理相关记录；
- 自动保存首次开启时显示明确提示。

## 十二、异常情况

### 媒体已删除

- 显示“该媒体已不可用”；
- 1 秒后自动跳过；
- 不创建空文件。

### 网络中断

- 暂停连续浏览；
- 保留当前媒体；
- 网络恢复后重试；
- 不无限快速跳过整个队列。

### 不支持的视频格式

- 显示“不支持播放”；
- 提供手动下载；
- 连续模式下按照设置跳过。

### 频道历史尚未加载

- 接近当前队列末尾时继续请求媒体消息；
- 加载期间显示“正在加载更多”；
- 确认没有更多媒体后才结束队列。

### 应用最小化或电脑休眠

- 暂停图片倒计时；
- 暂停自动切换；
- 不在后台连续保存大量内容；
- 恢复窗口后继续当前项。

### 媒体切换过快

- 取消已经失去意义的预加载任务；
- 只保留当前项和下一项；
- 防止短时间创建大量下载任务。

## 十三、第一版 MVP 范围

第一版只完成以下功能：

1. 当前频道媒体连续浏览开关；
2. 图片按照固定时间自动切换；
3. 普通视频结束后切换下一项；
4. 图片、视频、图片加视频三种筛选；
5. 暂停、继续、上一项、下一项；
6. 预加载下一项；
7. 队列结束后停止；
8. 当前频道范围内继续动态加载媒体；
9. 浏览时自动保存开关；
10. 图片和视频分别控制是否保存；
11. 文件大小限制；
12. 重复媒体跳过；
13. 受保护媒体禁止保存；
14. 下载失败不阻断浏览；
15. 设置持久化。

## 十四、第二阶段功能

第二阶段再考虑：

- 每个频道独立设置；
- 随机浏览；
- 收藏媒体队列；
- 从指定日期开始；
- 只浏览未看过的媒体；
- 记住上次浏览位置；
- 下载历史和完整任务管理器；
- 下载限速；
- 每日保存上限；
- 自定义文件夹和命名模板；
- 多频道媒体播放列表；
- 等待频道发布新媒体后继续；
- 图片转场效果；
- 遥控器或鼠标额外按键支持。

## 十五、明确不纳入第一版

第一版不做：

- 一键下载整个频道；
- 无上限后台爬取历史媒体；
- 跨频道自动浏览；
- 绕过禁止保存保护；
- 自动转发媒体；
- AI 内容识别和分类；
- 云端媒体备份；
- 自动删除 Telegram 原消息；
- 移动端后台长时间下载。

这样可以把第一阶段控制在“改造现有媒体查看器”，而不是扩展成一个复杂的 Telegram 下载管理器。

## 十六、核心验收标准

### 连续图片

用户打开频道图片并开启连续浏览，图片加载完成并经过设置时间后，应进入下一张图片。

### 连续视频

用户进入普通视频，视频播放结束后，应自动进入下一项并按照媒体类型继续播放或计时。

### 手动暂停

用户暂停连续浏览后，图片不再计时，视频结束也不进入下一项。

### 手动切换

用户手动点击下一项后，连续模式保持开启，新项目重新开始播放流程。

### 自动保存关闭

自动保存关闭时，连续浏览过程中不得向系统下载目录写入新文件。

### 自动保存开启

自动保存开启时，只保存真正成为当前项且符合规则的媒体。

### 内容保护

受保护媒体不显示自动保存结果，也不能通过连续浏览绕过限制。

### 网络失败

单个媒体加载失败时允许跳过；连续失败达到阈值后应暂停并提示，而不是无限跳过。

### 队列结束

到达当前频道媒体末尾且没有更多媒体时，应停止连续浏览并显示“已浏览完毕”。

从代码结构看，最关键的改动点会集中在 `MediaViewerSlides` 的切换控制、`VideoPlayer` 的结束回调、媒体查看器状态以及设置存储；现有手动下载入口和内容保护判断可以直接复用。当前播放器还会循环 GIF 和短视频，因此第一版必须明确修改连续模式下的循环规则。
