# Telegram TT 第一版开发计划

## 目标

在现有 Telegram Web A 的媒体查看器中实现“频道连续媒体浏览”。第一版以观看体验为核心：用户在频道中打开图片或视频后，可开启连续浏览、暂停或切换媒体，并按设置自动保存实际打开且允许保存的媒体。

## 当前状态

第一版已完成实现：连续浏览状态与缓存迁移、频道内控制条、媒体筛选、图片计时、视频结束推进、动态加载等待、自动保存和“数据与存储”设置均已接入。已完成本地化类型生成、TypeScript 编译和 SCSS 检查；需要使用已登录账号在真实频道中按本文的场景表进行最终人工验收。

## 范围与边界

### 纳入第一版

1. 仅在频道消息的媒体查看器中显示连续浏览控制。
2. 支持图片、视频、图片和视频三种筛选方式。
3. 图片加载完成后按可配置时长自动切换。
4. 普通视频播放结束后自动切换；连续模式下不让短视频循环阻塞队列。
5. 支持开启、关闭、暂停、继续、上一项、下一项和键盘快捷键。
6. 复用现有相邻幻灯片预加载能力，仅预加载下一项。
7. 队列临近末尾时复用现有频道媒体搜索继续加载；确认无更多项目后停止。
8. 提供“浏览时自动保存”开关、图片和视频保存类型开关、单个文件大小上限。
9. 不保存受保护、付费、不可下载或超出限制的媒体；下载失败不影响浏览。
10. 持久化默认开关、图片时长、筛选和自动保存配置。

### 不纳入第一版

1. 批量下载整个频道、跨频道浏览或后台无限加载。
2. 频道独立设置、下载历史、下载限速、文件夹和命名模板。
3. 云端备份、内容识别、绕过内容保护或付费限制。
4. 随机播放、循环队列、等待频道新媒体和记住浏览位置。

## 已确认的现有基础

| 能力 | 现有位置 | 复用方式 |
| --- | --- | --- |
| 媒体查看器与前后项目 | `src/components/mediaViewer/MediaViewer.tsx` | 基于现有 `getNextItem` 生成连续队列 |
| 相邻项目预加载 | `src/components/mediaViewer/MediaViewerSlides.tsx` | 保持左、中、右三页渲染，仅预加载下一项 |
| 图片与视频渲染 | `src/components/mediaViewer/MediaViewerContent.tsx` | 在媒体就绪后启动图片计时或自动保存 |
| 视频结束处理 | `src/components/mediaViewer/VideoPlayer.tsx` | 将连续模式的结束事件交给浏览控制器 |
| 动态媒体加载 | `searchChatMediaMessages` | 接近已加载队列边缘时继续查询当前频道媒体 |
| 下载与内容保护 | `downloadMedia`、`selectIsMessageProtected` | 仅调用已有下载入口，并沿用保护判断 |
| 本地持久化 | `global.mediaViewer`、`src/global/cache.ts` | 增加缓存迁移和默认配置 |

## 实施阶段

### 阶段 1：状态模型与持久化

改动位置：

- `src/types/index.ts`
- `src/global/types/globalState.ts`
- `src/global/types/tabState.ts`
- `src/global/types/actions.ts`
- `src/global/initialState.ts`
- `src/global/actions/ui/mediaViewer.ts`
- `src/global/cache.ts`

工作内容：

1. 增加持久化的连续浏览设置：默认启用、图片停留时间、媒体筛选、自动保存、图片保存、视频保存、大小上限。
2. 增加仅在当前媒体查看会话存在的状态：是否启用、是否暂停和浏览方向。
3. 增加更新会话状态与持久化设置的全局动作。
4. 将缓存版本升级并补齐旧缓存的默认值。

验收：重启应用后配置不丢失；关闭媒体查看器后本次会话的播放状态不恢复。

### 阶段 2：连续浏览控制条与交互

改动位置：

- 新增 `src/components/mediaViewer/MediaViewerContinuousControls.tsx`
- 新增对应样式文件
- `src/components/mediaViewer/MediaViewer.tsx`
- `src/components/mediaViewer/MediaViewerSlides.tsx`
- `src/assets/localization/fallback.strings`

工作内容：

1. 仅在频道消息媒体查看器中显示控制条。
2. 提供开关、暂停/继续、上一项、下一项、当前筛选和自动保存状态。
3. 接入 `Space`、方向键、`A`、`D` 和 `Esc`，并避开输入控件。
4. 手动切换后保留连续模式，更新后续自动浏览方向。
5. 结束时停止连续模式并给出“已浏览完毕”的提示。

验收：用户可以完整控制一个连续浏览会话，非频道、头像、网页媒体和受保护媒体不显示该能力。

### 阶段 3：自动切换、筛选与预加载

改动位置：

- `src/components/mediaViewer/MediaViewer.tsx`
- `src/components/mediaViewer/MediaViewerSlides.tsx`
- `src/components/mediaViewer/MediaViewerContent.tsx`
- `src/components/mediaViewer/VideoPlayer.tsx`

工作内容：

1. 图片在可显示后开始倒计时；窗口隐藏、页面后台、拖动缩放或手动暂停时停止并重置倒计时。
2. 普通视频结束后推进到下一项；连续模式下短视频只播放一次。
3. GIF 按图片时长推进，不等待无限循环。
4. 根据筛选跳过不匹配的媒体；跳过受保护或未解锁的付费媒体。
5. 沿用右侧预渲染作为下一项预加载；动态加载期间等待而非错误结束。

验收：图片、长视频、短视频和混合队列都能按预期推进；网络加载时不会快速跳过。

### 阶段 4：浏览时自动保存

改动位置：

- `src/components/mediaViewer/MediaViewerSlides.tsx`
- `src/components/mediaViewer/MediaViewerContent.tsx`
- `src/components/left/settings/SettingsDataStorage.tsx`

工作内容：

1. 仅在媒体成为当前项且已实际打开后调用现有 `downloadMedia`。
2. 按图片、视频开关与单个文件大小限制筛选。
3. 遵守现有受保护、付费和下载权限判断。
4. 会话内按媒体哈希去重，关闭连续浏览后不再创建新的自动保存任务。
5. 在“设置 → 数据与存储”中提供全部持久化选项。

验收：关闭自动保存时不创建下载任务；开启后只下载符合规则的当前媒体；下载失败不阻止后续浏览。

### 阶段 5：静态检查与人工验收

1. 运行 `npm run lang:ts` 更新本地化类型。
2. 运行 `npm run check:ts` 和 `npm run check:css`。
3. 使用真实频道按下表完成手工检查。

| 场景 | 预期结果 |
| --- | --- |
| 连续图片 | 图片完成加载并到时后进入下一项 |
| 图片加载慢 | 加载过程不计入停留时间 |
| 连续视频 | 视频结束后进入下一项 |
| 手动暂停 | 图片不倒计时，视频结束不切换 |
| 手动下一项 | 连续模式保持开启，新项目重新开始流程 |
| 类型筛选 | 仅展示所选图片或视频 |
| 队列末尾 | 动态加载完成且无更多媒体后停止并提示 |
| 内容保护 | 不自动保存受保护或付费媒体 |
| 自动保存关闭 | 不新增系统下载 |
| 自动保存开启 | 仅保存当前实际打开且在限制内的媒体 |

## 技术决策

1. 不新增第三方依赖，所有状态和下载行为都复用现有全局状态、媒体缓存和下载管线。
2. 浏览队列不单独持久化；它由当前频道已加载媒体和动态搜索结果临时构成。
3. 自动保存只复用 Telegram 现有下载流程，不自行扫描用户磁盘或修改下载目录。
4. “重复文件跳过”在首版先以当前连续浏览会话的媒体哈希去重实现；跨会话的系统下载目录去重需要桌面端下载历史，放在后续阶段。
5. 所有新增界面文本进入 `fallback.strings`，不在组件中硬编码。

## 实施顺序

先完成阶段 1 和阶段 2，形成可开关、可暂停的控制框架；随后接入阶段 3 的自动推进，再完成阶段 4 的自动保存。每个阶段完成后都先进行静态检查与代码复核，避免在媒体查看器这一高频路径上引入性能回归。
